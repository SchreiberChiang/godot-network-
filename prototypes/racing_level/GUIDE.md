# Port Loop 港区赛道候选

原创低多边形几何场景；仅依赖本目录。供后续赛车接入，不包含驾驶、圈数、胜负、联机或账号实现。基准 `0da5395ba0e0858385c9c9a8c432807756771a6c`，候选分支 `codex/racing-level`。不替换已有 V1 车样本。

## 本机查看

在 F 盘本工作树内双击 `Preview.cmd`，调用指定的 Godot 4.7.2：

```text
D:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe
```

1. `1` / 底部 DIORAMA：斜俯视全景。`2` / ROUTE PLAN：俯视完整路线。
2. `3` / HAIRPIN：看发卡弯。鼠标右键拖动环绕，滚轮缩放。
3. `C` 显隐检查点标记，`G` 显隐八辆几何比例占位车；`Esc` 退出。

不是驾驶试玩；车辆只是无碰撞的尺度参照。窗口键鼠交互尚未做人工逐键验收；镜头切换在真实截图流程中执行，环绕状态经独立源码审查修正。

在本目录运行可复现检查：

```powershell
.\Preview.cmd -Mode Validate
.\Preview.cmd -Mode Capture
```

每次独立进程的 APPDATA、LOCALAPPDATA、USERPROFILE、HOME、XDG 和 TEMP/TMP 均指向本目录 `artifacts/<mode>-<timestamp>/`；父进程环境不变。日志和截图同目录。不运行主工程入口，不需要网络、插件或导出模板。Validate/Capture 超过 120 秒仅终止该次创建的进程句柄并保留失败。每种用途默认保留最近两份运行目录；旧目录先核实绝对路径、run.json 归属、链接及进程，再保留日志/结果/哈希至 `artifacts/history/<run>/` 后移除。未完成、归属不符或活动目录不自动删除。

`.gdignore` 阻止主项目递归导入；本目录可直接作为独立 Godot 项目。`harbor.tscn` 在实例化时执行 `harbor.gd` 生成场景；`viewer.tscn` 仅增加灯光、相机和查看界面。无第三方素材。

## 几何规格

| 项目 | 实际值 |
|---|---|

| 中心线长度 | 458.09999 m（含起伏的三维弧长） |
| 采样 | 335 段，最大间距 <1.5 m；末点重复首点 |
| 主路 / 缓冲 | 10 m 主路，两侧各 3 m；分段中点实测最窄 9.97859 m |
| 缓弯 / 发卡 | 外侧 20 m、18 m；东侧发卡 14 m 中心线半径；内部两个 10 m 转弯 |
| 起伏 | 北直道 x=-22..18、z=-48；正弦平方剖面高约 2 m，最大采样坡度 15.674%（约 8.91°） |
| 碰撞 | 16 m 连续三角网格路面 670 三角面；两侧 670 个静态护栏碰撞形状 |
| 起跑格 | 两列四排，预留单车 2.4×4.2 m；横向净间距 2.6 m、纵向 1.3 m |

路面含缓冲带使用单一 ConcavePolygonShape3D，坡面与平面共用边。主路、白线和路肩色块只是覆盖其上的可视层，不增加台阶碰撞。护栏高 0.72 m，中心偏移 ±8.4 m，相邻段有 0.10 m 搭接。仓库/集装箱/码头/灯杆等有静态碰撞，细小装饰不全部碰撞。车身占位体不参与碰撞。

## 接入数据与坐标

唯一生成来源为 `track_data.gd` 的 `create()`。返回 Dictionary；Validate/Capture 都导出同样的 `layout.json` 供离线审阅。JSON 中 Vector3 转成 `[x,y,z]`，浮点数单位米，角度单位弧度。这是本地关卡数据，不是框架网络协议，也不新增重复的 schemas 契约。

- 原点在岛体中心，Godot +Y 向上，+X 朝东、-Z 朝北；平路面 Y=0.12。模型自身车头 -Z。
- `samples` 包含 `position / forward / right / distance_m`；末点是首点的闭合副本，通常遍历 `size-1` 段。`forward` 是三维单位切向；`right = forward.cross(UP).normalized()`。当前路线无交叉，方向始于西侧起终点向北，沿北直道向东。
- `checkpoints` 的 `id` 连续递增；`sample_index` 引用中心线，`position` 是地面锚点，`forward` 为沿行驶方向的平面法线，`right` 是宽度方向，`half_width_m=8.25`，`height_m=6` 是地面向上的覆盖高度。局部 up 可用 `right.cross(forward)`。
- 接入者用运动线段与检查点平面求交，检查由负侧进入正侧，并在交点检查横向宽度及高度，不能只看距离或某一帧位置。还需由 race_rules 自己处理顺序、防漏圈、重生和终点门禁；本候选不实现这些规则。
- 发车点在终点负侧：先越过 0 发车，再按 1..11、0 顺序；初始接触、重生和逆行不能自动算圈。此段是接口接入建议，不宣称已有规则行为。
- `spawns` 含稳定 `id=0..7`、`position`、`forward`、`yaw_rad` 和 `reserved_size_m`。所有车头 -Z/yaw=0。位置 Y=0.77 是原型车身参考点，实际车辆按轮胎/悬挂调整高度，不应直接当车轮接地点。
- 新资源直接采用 -Z 车头。若将旧 +X 车头 V1 样本接入，可仅对模型子节点加 Y 轴 +90° 旋转；不要旋转数据轴、规则节点或覆盖旧资源。本任务没有读取或转换该样本。
