# 港区单车离线街机驾驶

项目根目录双击 **OpenRacing.cmd**，用已有 Godot 4.7.2 建立独立小工程并打开窗口。当前是单人一圈练习，不联网：3秒倒计时后发车，越过起跑线才开始计时。按顺序经过检查点01至11，再回到起终线完成一圈，显示圈速并停车。错过检查点必须补过，逆向或重复穿线不会计分。R或完赛后的“重开练习”清空整场进度、成绩和氮气，重新倒计时；参数保留。失焦时车辆、倒计时和圈速一起暂停。

车会自动向前加速。A / ← 左转，D / → 右转；同时按两个方向先制动，停下后直线倒车，倒车限速为普通极速的四分之一。松开双键会逐渐恢复向前行驶。空格或屏幕任一“氮气”按钮触发同一个动作，R 重开整场练习并清空氮气，F2 实时调参，M 静音/恢复，TAB 全景，ESC 退出；窗口失去焦点会暂停。

氮气初始为空，实际高速侧滑才能充能，最多三槽。每次点击消耗一槽、喷射 1.5 秒；再次点击追加时间，推力不叠加。已经激活的喷射不能取消；双方向仍能制动，但喷射结束前不能倒车。制动或实际后退时拒绝新喷射，不扣槽。左右屏幕氮气按钮共用资源，同时按住不重复消费；全部松开后再按才算下一次点击。

## 调整俯视角与画面远近

运行 OpenRacing.cmd 后按 F2：

- **俯视角**：35–85°，越大越垂直；默认56°，按用户本次反馈固化。
- **视野**：12–50m，越小车在画面里越大；默认44.5m，按用户本次反馈固化。正交相机用视野调整画面大小。

两项相机参数与八项驾驶参数分开；R重开和驾驶预设保留当前视角，退出重开恢复默认。复制按钮仅复制驾驶JSON。窄于900px的窗口打开F2会暂停驾驶并隐藏HUD，收起后恢复自己创建的暂停；失焦暂停仍需点“继续驾驶”。

可以用Godot打开根project.godot，但它的主场景是host/main.tscn（框架宿主），不是赛车。赛车相机在arcade_main.gd运行时创建并每帧更新，不能在根场景Inspector中直接调整。普通编辑器会生成.godot缓存、脚本旁.gd.uid、资源旁.import等；.godot已忽略，UID/import尚未统一忽略，可能成为Git待审查的新文件。当前建议使用F2；启动器将赛车输入、导入和环境放在artifacts/racing-offline/<run>/，共享editor_data缓存另见下文。

## 当前运动方式

默认采用“玩家调校”：最大转向请求 120°/s、转向/松方向侧滑保留率 0.97/0.989、加速度 24 m/s²、普通极速 30 m/s，直线倒车上限 7.5 m/s。驾驶、氮气和擦墙共八项已按用户反馈“就这个了，非常不错”的[最新参数v2](../../../docs/assets/racing/handling-approved-20261003-v2.json)固化，先前五项调参记录保留作历史。主要借鉴最新 TopDownCarController 的前向/横向速度分解与保留横向惯性；更新顺序、碰撞和氮气为本项目实现，不是已核实的 SkidStorm 原代码移植。旧 DriftLogic 仅作机制比较，没有实现其漂移状态迟滞。

按 F2 打开右侧面板，先是两项相机、四项视觉悬挂与音效开关，再是八个驾驶滑条作用于下一物理步：原五项，加氮气极速倍率、氮气额外加速度、擦墙阻力。可切换“玩家调校”“参考街机”“原参数”，不重置动量或氮气；后两项仅对照旧驾驶参数，也采用本轮碰撞修复。R 清空动量和氮气、保留参数；重开恢复玩家调校。面板可滚动查看底部参数和“复制驾驶参数”（真实剪贴板按钮仍待人工验收）。

氮气默认采用普通极速 ×1.53999995231628（约 46.2 m/s），额外加速度 60 m/s²；两项分别可调至 ×1.8、60 m/s²。保存用户原始精度，面板显示约 ×1.54。喷射结束时将已经获得的超速以 20 m/s² 收回到普通极速，不再一帧硬截，也不能重新加速到过期的氮气上限。双方向制动仍占优，即使额外加速度拉满也至少有 18 m/s² 的直线净制动力；喷射期间不能倒车。

**保留率越大越滑**：0.2 表示参考时间步内仅留下 20% 横向速度，通常更抓地；0.95 留下 95%，收尾更慢。这里以 50 Hz 作为换算基准，实际仍跑 60 Hz，用 `pow(keep, dt / 0.02)` 维持时间口径；截图没有给出 Unity 的真实时间步，所以 50 Hz 是明确选定的调参基准。试调时先只改一个数，例如比较 0.2 / 0.95 的抓地，再改松键保留率观察甩尾收尾。

arcade_vehicle.gd 使用 60 Hz 平面运动：车头转向与世界惯性分开，持续转弯产生侧滑，松转向后逐渐恢复抓地。转向速度按前向速度 /8 缩放，达到 8 m/s 后用设定值；倒车不转向。转向且前向速度大于 6 m/s 时用转向保留率，否则用松方向保留率；这条切换保留，尚未证明是其它怪感的原因。

四轮视觉悬挂每物理步最多4条射线，限幅弹簧/阻尼只作用于轮位和车壳，固定Y与驾驶八值保持。F2可调行程0.08–0.30m、响应2–6Hz、阻尼0.6–1.2、倾斜0–6°；默认0.18m/4Hz/0.9/4°。初始化及R先采样一次，普通暂停/倒计时冻结。真实爬坡/腾空另设阶段。方案、数量预算和验收边界见 [当前反馈计划](../../../docs/17_framework_shooter_plan.md#racing-feedback-20261004)。

CharacterBody3D 每物理帧执行一次实际滑动碰撞，一个连续横向胶囊覆盖车身。保留引擎解完所有滑动面的速度，擦墙阻力以 `exp(-阻力*dt)` 每步施加一次，不再每个接触都乘 0.82。玩家默认阻力 6.2，参考/原参数仍为 0.8；较大的值在持续接触时减速更多，本轮分别验收这两种设置。转向采用覆盖中间姿态的保守旋转包络。贴静态墙转向开放侧但尾部空间不足时，可请求离墙助力，总量最多 10 cm/步且不超过 6 m/s；同一墙法线去重，接触记录最多保留 0.12 秒且核验对象仍存在。它仍由同一次引擎碰撞 sweep 执行、不直接改位置、不忽略墙，解算后的世界惯性保留；朝墙内转向继续拒绝。正撞时仍可能停住，双键倒车可退出。用户已认可这组实际驾驶参数，手感反馈不代表联网或所有碰撞情形通过；完整离线圈的自动实车验收见下方。

港区在这个入口使用平面变体，车的 Y 固定。车身倾斜、四条接地射线驱动的轮位、前轮转向与四轮滚动属于视觉悬挂；相机可调俯视角度、跟位置，不跟着车头旋转。旧力式 vehicle.gd、旧坡道默认数据和测试源码仍保留作历史依据，当前入口已经改用街机版本。此原型不代表真实悬挂、跳跃、多人车辆碰撞或服务器接入。

## 胎痕和声音

悬挂面板的行程是相对中立轮位的单侧限幅：默认±0.18m，最大±0.30m，不是双向总长度。车壳贴地修正另限于±0.20m；这些数值不改变车身碰撞或真实垂直运动。

后轮实际高速侧滑时留下胎痕，按0.2m采样，8秒淡出，最多4096段与8个固定网格；R清空，暂停冻结。只有实际接地且处于漂移充能条件才画，倒车/异常跳段断开。怠速、行驶、轮胎、氮气、碰撞和倒计时共六种原创音效，固定六个播放节点；M或F2声音开关静音。ESC和窗口关闭先停止音效再退出。默认音量仍需用户试听，不以波形/自动测试声称听感通过。

## 环境、复验和隔离

本机引擎为 4.7.2.stable.steam.ed1daf0bf。默认路径 D:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe；安装位置不同可运行 OpenRacing.cmd -Godot "<实际路径>"。没有自动下载、安装或修改全局配置。

OpenRacing.cmd -Mode Verify 会短暂打开窗口：新工程首次冷导入、二十八脚本 --check-only、HUD、规则、过线检测、反馈专项/实际窗口、驾驶物理/实际窗口、练习整圈/实际窗口分别记退出码。首次冷导入失败不会以热导入掩盖。证据保存在主检出的 artifacts/racing-offline/，本轮反馈验收在 logs/racing-feedback-20261004/；用户默认镜头复验在 logs/racing-camera-20261004/；此前HUD验收轻量记录在 logs/racing-hud-20261003/；练习圈历史在 logs/racing-practice-20261003/；最终参数记录在 logs/racing-approved-handling-20261003/；旧记录在 logs/racing-nitro-contact-20261003/、logs/racing-tuning-20261003/ 与 logs/racing-arcade-20261003/。真实数量、失败及未验范围见 [练习圈验收](../../../docs/17_framework_shooter_plan.md#racing-practice-20261003) 与 [最终参数验收](../../../docs/17_framework_shooter_plan.md#racing-approved-handling-20261003)。

源码路径相对项目根；临时工作树也把运行输出放到主检出 F 盘。引擎采用 ._sc_，共享编辑器缓存留在 runtime/editor_data，每次项目 .godot、HOME/XDG/TEMP 都新建；不能称所有缓存全独立。入口一次只允许一个实例，收尾只处理自己创建的进程。街机 Play / Verify 分用途各最多两份，不挤掉旧力式专项的历史记录；清理失败如实保留。
