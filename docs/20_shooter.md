# 横版射击示例与接入边界

射击游戏位于 `examples/shooter/`。它是通用 SDK 的使用方：枪械、生命、地图、死亡与复活规则只在该目录，核心服务只保存已确认的资产和配置。账户界面、房间列表和背包使用可复用的 `examples/framework/` 客户端外壳；实际整合和导出验收以 STATUS 为准。

## 玩法

“零号仓库”是一张 960×540 的平台地图。A/D 移动、空格跳跃、鼠标瞄准和左键射击。两名玩家开始五分钟自由混战；服务器判定移动、碰撞、射速、即时命中、遮挡、伤害和死亡。没有换弹、技能、命中回溯或反作弊产品。

| 武器 | 单弹伤害 | 最小间隔 | 射程 | 特点 |
|---|---:|---:|---:|---|
| 基础步枪 | 25 | 220ms | 850 | 初始拥有，单发直线 |
| 冲锋枪 | 12 | 90ms | 570 | 小幅服务器散射 |
| 霰弹枪 | 18 | 800ms | 350 | 一次六颗散射弹丸 |

属性来自同目录 `game_config.json`，价格与所有权来自通用资产目录。默认 100/200 金币解锁冲锋枪/霰弹枪。购买不自动选用。玩家在大厅或死亡时选择已拥有武器，服务器确认后保存默认配置；存活时拒绝修改。管理员调整默认配置也不会把存活中的实际武器立即替换。

死亡至少等待三秒，再手动复活。选枪或购买尚未完成时禁止复活。复活请求通过适配器要求宿主重新读取已保存资产；确认成功才生成玩家，失败则仍保持死亡并允许重试。失效配置退回基础枪且显示原因。

## 接口与安全边界

- 客户端只有 `send_input(move, jump, aim, fire)` 和 `send_respawn()`。输入无坐标、时间、伤害、装备或所有权字段，严格 Schema、有限数、单调序号和每秒 90 次上限校验。输入超过 250ms 未更新时停止移动和射击。
- 世界快照使用 `shooter_state.schema.json`，只接受服务器和不倒退的 tick；真实射线与角色均来自服务端快照。物理分步避免延迟帧穿过薄平台。
- 适配器实现 `asset_context`、`on_asset_state`、`set_asset_busy`，通过通用 `asset_refresh_requested(user_id, operation)` 请求刷新。完成和取消分别调用 `complete_asset_refresh(user_id, operation, state)` 与 `cancel_asset_refresh(user_id, operation)`；通用 SDK 不解释 operation，射击适配器才将自己的 `respawn` 标签映射为复活。
- 一名成员同时只能有一项资产操作。初始入房资产等待与在途操作上限均为 60 秒；刷新超时取消，未知结果的写操作超时会结束该成员连接，防止在旧写入仍不确定时继续状态转换。旧成员代次的回包不能影响重新入房者，重复完成也不能重复出生。
- 同一角色只按服务器状态接受击杀，尸体不会重复计分；最近 192 条射线有界保存，只显示 160ms。账号身份是稳定 user_id，不是网络 peer。
- 已完成回合发出 `round_finished(match_key, players)`；适配器提交 `shooter_result.schema.json` 结果。断服中止不提交 completed，因此不会发正常完局奖励。
- 回合参与时间只累积实际在房时间，断开期间不计。整局完成后参与至少 60 秒，奖励 20＋5×击杀数金币。宿主的 `rewards.gd` 重新计算，忽略房间宣称的 credits；重复玩家或参与时间超过局长不发奖励。事务和幂等由通用持久服务负责。

## 当前独立测试

`tests/test_shooter.gd` 是真实 Godot 执行的纯玩法测试，不是跨进程或跨电脑联机证据。可由单元总入口加载，也可运行 `examples/shooter/test_runner.gd`。Windows GUI 子系统引擎必须等待真实退出，并检查 stderr，不能只看进程启动或结果标记。

测试覆盖输入伪造与过期、重复序号、碰撞与平台、薄平台穿透、射速、墙体遮挡、尸体重复击杀、死亡等待、事务期间复活拒绝、刷新失败与重试、失效装备回退、离房失效、参与时间、完成/中止奖励、重复玩家与伪造奖励。第一批独立测试 68 项通过；联机、界面和独立包应另行验收。

中文外壳 `examples/framework/client.gd` 使用 `--game=shooter` 或 `--game=turns` 与 `--connection-config=<公共 JSON 文件>`。密码只在输入框中交给加密账号接口，不写入命令行或保存。未确认的购买/选择只在客户端数据目录保存操作编号、物品及槽，重新登录同一账号后可查询/重试原操作，防止换一个编号重复扣款。

`examples/framework/preview.gd` 为源工程专用渲染夹具，真实 GPU 生成登录、注册、大厅、背包、账号、存活射击与死亡射击共七张截图；画面明确标记使用测试数据，不能当作真实登录或联机证据。它和 `examples/shooter/test_runner.gd` 不应复制进独立游戏包。

`tests/run_asset_callbacks.gd` 在 Godot 中执行通用资产生命周期专项，覆盖任意游戏操作标签、身份/成员代次、重复和迟到回包、忙状态、超时与初始资产先于成员确认，当前 32 项通过。

`tests/run_framework_clients.gd` 是一进程一真实客户端的测试入口，继承相同账号/背包界面与 SDK；私有 `--test-config` 文件只用一次，读后删除，报告不会保存密码或会话凭据。`tests/test_framework_clients.ps1 -Visual` 由已就绪的隔离 operator 测试环境驱动，读取 `run/operator-test-context.json` 指向的私有上下文，只管理自己创建并保留句柄的客户端及测试房间，不启动或停止父测试的管理服务。完整结果需读本轮实际 result.json，不能用渲染夹具或纯规则通过代替。

2026-09-22 真实专项：`powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_framework_clients.ps1 -Visual` 最终退出 0，47 项通过、0 项失败。两名真实 WSS/ENet 客户端完成注册、活着时伪造请求拒绝、实际击杀、死亡后解锁与幂等重试、选择、复活、退房重入；生产配置的五分钟对局完整结束，实际参与时间满足 60 秒门槛，数据库金币按 20＋5×击杀准确增加。另两名真实取石子客户端完成购买玉石主题、入房应用、在房修改拒绝与完整回合；重复登录、封禁撤销及解除封禁也通过。证据位于 `logs/operator-68c27ae5f8bb40de977cdebca3ac19c6/clients-a982c3c81bb5453e9e802048a58c0068/`。此结果是 Windows 本机真实多进程测试，不等于跨电脑局域网或独立导出包验收。

首次专项在注册前失败：父测试上下文误用了空的成功状态 `code` 作为邀请码，客户端正确拒绝无效选项；调整测试读取 `invite_code` 后才得到上述完整通过。没有删除或放松失败断言。

需要打包新游戏时，同目录的 `game.gd`、`adapter.gd`、`room.gd` 和 **`game_config.json`** 一起放入游戏目录，清单放项目根目录，并带 SDK 及对应 Schema。游戏不会直接读取数据库，也不需要旧资源。
