# 00 从零开发：M0/M1 的实施任务

> 本文为首轮历史任务。当前 `codex/shooter-framework` 分支按 [17：框架与射击分支计划](17_framework_shooter_plan.md) 推进；独立工程、禁止旧代码、真实验收原则继续适用。

这是新工程的开发规范，不是对已有代码的重构计划。不要寻找旧项目；所有核心和示例在当前目录新建。

## 范围与默认值

本轮只实现单机房间生命周期，不实现真实客户端入房和完整大厅 UI。宿主使用 Godot/GDScript；首轮优先在用户当前 Windows 环境验证，Linux 适配另行记录状态。不自动安装新版本或为方便测试而改用户全局配置。

M1 可用本地测试驱动直接调用 RoomManager，不必先完成公共 WebSocket 大厅；但不要为了测试先造一套旧 ENet 大厅接口。M2 从头实现标准 WebSocket JSON 大厅。

新工程对外的网络接口默认只绑定回环地址，不开公网、防火墙和云资源。端口从测试配置分配，不继承旧服务器端口；所有默认值都可调整。

## M0：建立新的可重复基线

确认当前目录不是旧游戏仓库的一部分。保存本设计包；建立 host/、sdk/roomkit/、templates/、examples/minimal/、examples/turn_based/、tests/、tools/，但不以大量空占位代码充当实现。schemas/ 保持为唯一契约来源。

检测并记录可执行 Godot 的准确版本、路径、系统、Git 和导出模板可用性；不把 PIN_EXACT_TESTED_VERSION 当成可运行版本。形成环境文档，记录未具备的依赖。

建立最小宿主 Godot 工程与测试入口，可用 `--headless --path ...` 在开发阶段启动；命令中的真实路径、参数由实际环境验证后写进快速开始。开发工程启动通过不等于专用服务器导出已验证。

Git 可在新目录初始化；不清空已有目录、不重置用户仓库、不触碰全局身份。维护 STATUS.md。

M0 验收：有明确环境、工程和测试入口；能在可用环境重复启动并正常退出，或清楚列明阻塞。未实际执行的启动不可标为通过。

## M1：最小生命周期

实现 GameRegistry：根据已注册清单找到可信产物。未知 game_id 和未注册程序拒绝执行。清单样例的 artifact 只是标签，开发启动描述必须由本地配置映射；远程请求不能传任意程序路径。

实现 ProcessLauncher：参数数组调用、不拼 shell 字符串；跟踪本次 launch_id 和进程身份。测试用的进程适配器与真实平台实现分开，不用 mock 掩盖真实能力缺失。

实现 PortAllocator/RoomManager：租约分配与生命周期改变一致；最终是否成功以子进程实际监听为准。进程启动失败、超时、异常退出均触发有界清理；未知进程不可随意 kill。失败房间的端口在确认安全前保持隔离。

实现 ControlTransport：4 字节无符号大端长度 + UTF-8 JSON，处理拆包、粘包、部分写入、发送队列、消息大小上限。认证本次房间控制凭据，并校验 room_id/launch_id；凭据不进入公开日志或命令行。

实现最小房间测试工程：不加载玩法、美术、角色或旧地图；使用实际分配的 UDP 端口；完成控制认证与注册，在绑定端口成功后报告 READY，持续心跳，响应停止并退出。

状态：ALLOCATING → STARTING → READY → DRAINING → STOPPING → STOPPED。失败路径不因写成 FAILED 就假设进程已经消失。具体控制消息 payload、失败码和测试随实现补齐，不能只靠外壳 Schema。

## 本轮验收

| 编号 | 必须检查的行为 |
|---|---|
| G00 | 记录实际 Godot/系统版本与执行路径；未运行状态明确。 |
| G01 | 正常创建、真实子进程注册、端口绑定后 READY、心跳、停止与回收。 |
| G02 | 程序不存在或无法执行时失败，分配资源最终回收。 |
| G03 | UDP 端口被另一进程占用时不误报 READY，不关闭占用者。 |
| G04 | 子进程不注册或不 READY 时启动超时，有界清理。 |
| G05 | A 房异常退出，B 房不被误关闭；A 资源按政策清理。 |
| G06 | TCP 半条、多条、部分写入得到正确消息；超限和非法消息被拒绝。 |
| G07 | 错误控制凭据、错误 launch_id 被拒绝，不污染有效实例。 |
| G08 | 连续创建/关闭至少 10 轮无本次遗留进程与端口租约；后续再跑 T23 的 100 轮。 |
| G09 | 仅回环测试；命令和日志不包含秘密；不修改项目外代码或配置。 |

本轮不要求 T01—T25 全部通过；这些覆盖后续阶段。每项 G 测试都写明“已通过、失败、未运行”，并标明是真实 Godot 进程还是模拟。
