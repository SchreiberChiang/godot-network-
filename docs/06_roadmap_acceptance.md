# 06 开发顺序与验收

新仓库、从零实现；无需旧项目或旧源码。各阶段以真实验收结果推进，不按日历承诺工期。M0/M1 细则见 docs/00_greenfield_start.md。

## M0：建立全新工程基线

核对当前目录和真实 Godot/Git 环境；锁定可执行版本，建立宿主、测试工程和目录；记录可重复命令；初始化或沿用当前新仓库的 Git，不读取其它旧游戏。

完成条件：新工程可重复启动退出，有明确测试入口与环境记录。缺失环境必须列为阻塞，不能伪造运行通过。

## M1：实现单间房生命周期

从零编写 GameRegistry、RoomManager、ProcessLauncher、PortAllocator 和带认证的 TCP 分帧协议。创建无玩法依赖的测试房间，通过 launch_id 完成启动/注册/实际监听/ready/heartbeat/stop/回收。

完成条件：docs/00 的 G00—G09 有真实报告；正常启动停止、程序不存在、端口占用、启动超时、异常退出与分帧测试正确。模拟、开发工程与导出产物分别记录，不混用结论。

## M2：实现双端 SDK 与完整接入

从头实现标准 WebSocket JSON 大厅与独立 ENet 房间连接；本地开发身份、席位预留、一次性票据、认证门禁、共享联网入口、版本检查和场景就绪；两个新测试客户端加入后能回大厅。

完成条件：客户端只用 SDK 公开接口完成流程；非法票据不能生成玩家；没有绑定某种角色场景。公网开放前另过安全门禁。

## M3：从零编写第二玩法验证通用性

第一个示例新写最小方块移动，第二个新写无 CharacterBody、无武器的回合选择游戏。不要复制用户任何旧项目。容量可配置到 16，不为验证框架制作完整美术。

完成条件：两个 game_id 同时开房、独立构建、不能越权进入；新增第二项目只改该项目适配器和注册配置，不改 host/core 与 SDK 核心。换皮不算第二玩法。

## M4：持久化、安全和故障闭环

完成结果幂等/outbox、身份提供方、WSS、实际验证的 ENet 安全传输、资源限额、启动重试上限、主服重启政策、管理员权限、日志脱敏和备份。存储适配从新库开始，不迁移旧项目账号。

完成条件：通过相关安全/并发/故障用例；安全传输未实现不能发布到不受控公网。

## M5：形成框架 v0.1 发布包

自动导出、安装/启动/停止/检查脚本、兼容矩阵、快速开始、故障排查和升级说明；对 16 人真实行为与多房并发压测。Windows 与 Linux 分别测试、分别记录。

完成条件：干净环境按文档完成安装及两个示例流程；记录实测容量，不以空房或静止连接估算正式负载。

## 最小验收矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| T01 | 创建一房、两客户端加入 | ready前不可入房，认证后才生成实体 |
| T02 | 第17人加入16人房 | 明确ROOM_FULL，不出现短暂17名正式成员 |
| T03 | 只剩1位，两人同时申请 | 原子预留，只允许一个人占位 |
| T04 | 创建请求响应丢失后重试 | 同一幂等key只创建一个房间 |
| T05 | 同一key换请求体 | 返回冲突，不复用错误结果 |
| T06 | 票据过期/重复/跨房/跨游戏 | 全部拒绝，无越权玩家生成 |
| T07 | 已核销票据连接中断 | 不能给新连接重用；可重新申请合法名额 |
| T08 | 同用户两次连接 | 执行明确单会话/替换策略，不重复占位 |
| T09 | 端口占用/进程启动失败 | 有界失败或换端口重试，无泄漏 |
| T10 | TCP拆包、粘包、部分写入 | 消息正确重组，不丢消息/误解析 |
| T11 | 超大/非法/未知消息 | 限流或拒绝，不崩溃、不无限分配内存 |
| T12 | 杀掉A房进程 | B房继续，A状态明确，资源最终回收 |
| T13 | 心跳线程活着、模拟卡死 | 健康检测不把A误判为正常 |
| T14 | 主服崩溃再启动 | 按v0.1政策退出/隔离遗留房，无重复认领 |
| T15 | PID复用/旧launch消息 | 不杀无关进程，不污染新房状态 |
| T16 | 结算ACK丢失再提交 | 一次持久化/一次业务副作用 |
| T17 | 同结果换ID/改payload | 最终结果唯一约束或冲突保护生效 |
| T18 | 正常结束时控制服务不可达 | outbox持久化并可恢复重试，非静默丢失 |
| T19 | 构建或游戏协议不兼容 | 接入阶段明确拒绝，而非RPC阶段报错 |
| T20 | 升级只部署新构建 | 旧房不被覆盖；旧客户端不误入新房 |
| T21 | 新项目接入 | 不改host/core与SDK核心 |
| T22 | 公网身份与加密 | 不发送明文密码/裸会话，证书验证失败时拒绝 |
| T23 | 本地连续开关房100次 | 进程、端口、保留名额最终归零；观察内存稳定性 |
| T24 | 16人真实输入/最坏玩法场景 | 记录步耗时、带宽与掉线；增加房间直至安全容量边界 |
| T25 | 场景慢加载/迟到加入 | 初始玩家、装备、对局状态完整；未就绪不收玩法输入 |

100次循环仅是最小冒烟测试，不是可靠性证明。延迟、丢包、突发输入、大量实体与全局容量上限都需要实测。
