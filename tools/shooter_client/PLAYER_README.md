# RoomKit 横版射击 · 玩家客户端

这个目录可以直接运行：不需要安装 Godot，也不需要解压。

1. 双击 `Client.exe`（`StartGame.cmd` 效果相同，保留作兼容入口）。
2. 第一次使用时，点“注册”，填入服务器主机给你的邀请码、用户名和密码；之后直接登录。
3. 在房间列表里选中一个房间，进入；也可以自己创建房间。A/D 移动，空格或 W 跳跃，鼠标瞄准射击。

目录里已经有目标服务器的公开连接配置（`connection.json`）和证书（`server.crt`），`Client.exe` 启动时会读取同一文件夹里的这两个文件。目录里不含账号数据、服务器私钥或管理员凭据。

客户端必须和服务器是同一版本（见 `client-version.json` 的 `build_id`）。服务器代码更新后，旧客户端登录后会提示“客户端与服务器版本不匹配”。这时，或者服务器地址变了，请让主机重新运行 `PreparePlayerClient.cmd`，把新目录整个发给你。`CheckClient.cmd` 可以检查文件是否完整。

## 本机数据与更新

运行后，设置、诊断和待确认的资产操作保存在 `Client.exe` 旁的 `client-data/`，与启动时的工作目录无关。账号密码和会话凭据只留在内存，不存到这个目录。目录不可写时会提示停止记录，不会悄悄改存到其它磁盘，也不阻止登录或游戏。

给别人发送诊断时，只发送客户端导出的脱敏报告；不要把 `client-data` 整个打包或放到 Git/Release。诊断日志使用有界存储，多开各自记录；磁盘预算用尽或写入失败时会停止记录并提示。不要在游戏运行时手动整理日志。

主机重新运行 `PreparePlayerClient.cmd` 前，先关闭该目录的所有客户端。工具只保留普通、无链接的 `client-data`，把它完整移入新版客户端；交换或迁移失败会恢复旧客户端和数据。其它新增或改动的文件仍会阻止替换，不会被自动删除。历史目录如果含 `client-data`，自动清理也会拒绝。

手工换目录时，先关闭客户端，保留自己的 `client-data`，再用匹配服务器的新程序；不要用朋友的本机数据覆盖它。给朋友发客户端请使用全新生成的干净目录或 Release 文件，不能复制已经玩过的整个目录。`CheckClient.cmd` 会提示本机数据存在以及发现的链接问题，不会把数据加入程序校验清单。

旧版 `data/client-operations` 只作为一次性迁移输入识别，不是新的运行目录豁免：只有完全符合旧回执格式、无链接且没有其它文件的目录才会整体改名保留到 `client-data/legacy-client-operations/client-operations/`。原始字节和 operation_id 不变，空目录也保留；原有隔离目录冲突或任何未知、损坏内容都会拒绝更新并保留原目录。交换或迁移失败会恢复完整旧目录。此步骤不推测服务器归属、不联网、不自动补发；登录后仍需在客户端显式确认旧操作对应的服务器。


## 诊断读法

游戏底部显示 FPS、最近一秒最慢帧、房间 RTT、可靠发送丢包估计和快照更新时间；“网络详情 / 报告”可展开 RTT 波动、ENet 收发速率、连接阶段、固定错误类别及有足够样本才显示的窗口分位数。RTT 是往返时间；波动是 ENet 平滑绝对偏差，不是标准差。快照间隔不能直接换算丢包率。

可靠发送丢包估计按 Godot 4.7.2 的 PEER_PACKET_LOSS / 65536 × 100 显示，只反映 ENet 可靠发送的平滑估计。首个可确认的完整约 10 秒周期前显示“统计中”；空样本显示“—”。它不是所有 UDP 或下行快照的丢失率，短回环连接的零值不证明真实公网无丢包。

诊断每秒取一次白名单数值，异步写入 client-data/reports/ 的 JSONL；没有账号名、密码、令牌、邀请码、聊天或协议正文。“标记刚才卡顿”只写固定标记，“打开报告目录”打开这一脱敏目录。发送时只选这些 JSONL 文件。每会话最多 2 MiB、保留最近两份已结束会话、日志总预算 16 MiB；多开活跃文件不会互删。异常退出留下的活跃文件或预算锁不自动猜测归属清理，容量满或锁不可用只停记提示。

旧回执确认归属后仍保留原始 operation_id；“迁入”不触发请求，查询 / 重试仍需另按原按钮。若迁入中断，只能显式重试同一服务器；无法确认来源时保留原文件，不向另一个服务器补发。
